## 1. 结论与边界

直接进入业务后端阶段，不单独交付临时透明代理。保留 React + Rspack + Zustand 和成熟聊天界面，增加 Hono Node 服务、Neon PostgreSQL、Better Auth 登录，数据库成为聊天状态唯一权威来源。

核心原则：

1. 浏览器仅发送“用户输入 + 所选父消息 + 附件业务 ID + 生成选项”，不提交可信历史、用户 ID、上游 Key、任意上游 URL。
2. 服务端加载选定分支历史、验证归属、调用 DeepSeek、聚合增量、持久化最终结果及用量。
3. 保存完整消息树和内容块，复用当前协议语义，不能简化成只有 role/content 的聊天表。
4. 首期仍使用 DeepSeek Messages 协议载荷，通过自有 SSE 外层包装携带业务 ID、保存状态；不同时引入多模型通用协议或 AI SDK UI 协议。
5. 登录态使用 HttpOnly Cookie，模型 Key 只在后端。不是让前端把原来的 Key 传给代理。

**设计默认值，实施前可调整**：邮箱密码首发；单用户私有会话，无团队共享；生产 Hono 运行于 Vercel Node.js Functions + Fluid compute（本地仍用 Node 开发服务）；一会话同时一个生成任务；刷新/断开即取消生成，不承诺后台续跑或 SSE 回放；数据库用 Drizzle + pg；用户已取消邮箱验证/找回密码及 Google/GitHub OAuth；首次公网开放前仍须完成注册防滥用、登录限流和额度，不把邮件服务作为前置条件。

### 1.1 Better Auth 部署模式要明确

Neon 提供托管 Better Auth（Neon Auth），这是新建认证的可选默认路径；它的 SDK、认证 schema 和运维边界不同于自托管 Better Auth。本地首版已采用**自托管模式**：在 Hono 内挂载 Better Auth，认证表与业务表落到 Neon，方便同源 Cookie、统一部署和后续自定义 hooks。目前不再把认证部署模式列为本地开发阻塞项。若以后另行决定改用 Neon Auth，需单独设计变更，不同时部署两套登录。

本次文档修订不操作 Neon 资源；现有开发环境已建立。不迁移真实聊天、不读取现有浏览器 Key。为生产创建服务商 Key 和数据库凭据时，应由安全配置渠道提供，不能从 localStorage 自动搬运。

## 4. 认证、授权与数据隔离

### 4.1 自托管接入

Better Auth 的 handler 直接挂载到 Hono `/api/auth/*`，返回其原始 Response，保留 Set-Cookie，不套业务 JSON 包装。业务中间件通过 `auth.api.getSession({ headers: c.req.raw.headers })` 获取身份，无会话返回 401。[官方 Hono 集成](https://better-auth.com/docs/integrations/hono)

- 认证范围：邮箱密码注册、登录、退出、当前用户和 Cookie 会话。
- **用户已取消 P2-05（邮箱验证与找回密码）和 P2-06（Google/GitHub OAuth）**：不实现相关邮件、重置密码、第三方登录 UI/API，不等待 SMTP/发信域名/OAuth 配置。邮箱只作为登录标识，不声称已验证所有权；本产品没有自助找回密码功能。此范围变更不要求删除既有 Better Auth schema 或已实现代码。
- 认证表以锁定版本 CLI 生成的 `user/session/account/verification` 等 schema 为准，不自己发明密码/Token 字段，也不自行散列密码。
- Better Auth schema 经 Drizzle migration 管理；不把 `auth migrate` 和 Drizzle 当两套并行 schema 写入器。[Drizzle adapter](https://better-auth.com/docs/adapters/drizzle)
- 生产 Cookie 为 HttpOnly、Secure、合理 SameSite；本地 HTTP 仅在开发模式使用合适配置。
- 首期不启用额外 JWT，不把会话 token 放 localStorage，不引入无必要双 token 体系。
- 首期不启用 session cookie cache，避免额外撤销延迟；明确设置会话有效期和续期策略，不能假定所有缓存/token 都在退出时立即失效。[会话管理](https://better-auth.com/docs/concepts/session-management)
- 退出/账户切换时中止当前生成，清空当前用户内存缓存；IndexedDB 名称或键必须包含认证用户 ID。

### 4.2 同源优先

开发规范入口固定 `http://localhost:8095`，Hono 内部建议 `127.0.0.1:8096`。不要在 `localhost` 和 `127.0.0.1` 间混用，因为原有 Key/历史、Cookie 都受 origin 影响。新系统以空会话列表起步，不提供旧历史迁移界面。

生产使用同一 Vercel 域名提供静态前端和 `/api` 路由。若必须跨域，指定精确 CORS origin、credentials，配套 trustedOrigins；绝不 `*` 加凭据。所有业务写接口校验 Origin/CSRF；Better Auth 自己的防护不能自动覆盖业务路由。禁止绕过 CSRF 检查图方便。

### 4.3 归属与最小权限

每次查询使用 `WHERE id = ? AND user_id = session.user.id`；所有 parentId、messageId、attachmentId、generationId 都需交叉验证同用户、同会话。不可依赖 UUID 不易猜。对不属于本人资源统一返回 404；认证失败返回 401。

数据库不开放浏览器直连，不使用前端 Neon Data API。应用数据库账户只有必要表读写；迁移账户单独保存。可后续加 RLS 作为纵深防护，但不能假定 pooled connection 的 session SET 会稳定保留用户上下文。

## 5. 数据模型

统一业务 ID 为服务端 UUID；auth user ID 沿用 Better Auth 类型（通常 text），外键必须匹配。时间统一 `timestamptz`，API ISO 8601；前端适配当前毫秒时间。所有正文不进入普通日志。

### 5.1 表一览

| 表 | 主要字段与约束 |
| --- | --- |
| Better Auth 表 | CLI 生成；不要与聊天 conversation 混用 session 命名 |
| `conversation` | id、user_id、title、title_source(manual/auto)、root_message_id、revision、created_at、updated_at、deleted_at |
| `message` | id、conversation_id、user_id、parent_id、selected_child_id、role(user/assistant)、text、blocks(jsonb)、status、model、thinking、search、latest_reminder、prefix、stop_reason、stop_details(jsonb)、error(jsonb)、content_version、created_at、updated_at |
| `generation` | id、conversation_id、user_id、assistant_message_id、trigger_message_id、operation(send/regenerate/continue)、idempotency_key、request_hash、state、provider、model、request_options(jsonb)、last_sequence、lease_expires_at、started_at、ended_at、cancel_reason、error_code |
| `attachment` | id、user_id、name、mime_type、size、sha256、is_image、storage_key(nullable)、state、created_at、deleted_at |
| `attachment_provider_ref` | id、attachment_id、provider、credential_scope（非密钥标识）、remote_file_id、state、expires_at；唯一 attachment+provider+scope |
| `message_attachment` | message_id、attachment_id、position；联合唯一，保留附件顺序 |
| `usage_record` | id、generation_id(unique)、user_id、input_tokens、cached_input_tokens、output_tokens、tool_usage(jsonb)、raw_usage(jsonb)、completeness、created_at |
| `cleanup_job` | id、kind、resource_id、state、attempts、next_retry_at、last_error；远端删除失败可重试 |

可另加 `user_preference` 保存默认思考/搜索设置；不保存服务商 Key。消息最后一次 usage 用 generation 联表或 DTO 汇总，避免与 `usage_record` 两份权威数据。

### 5.2 消息树不能丢

现有类型包含 `parentId`、`selectedChildId`、`rootMessageId`。需存所有分支，不只是当前可见对话。示例：

```text
U1
 ├─ A1（原回答） → U2 → A2
 └─ A1b（重新生成） → U2b → A2b
```

- 发送：从所选父 assistant 延伸一个 user 和一个 assistant。
- 重生成：新增同一 user 下的 assistant 兄弟节点，不覆盖旧回答。
- 编辑 user：新建与旧 user 同父的兄弟分支，不覆盖旧问题及后续历史。
- 续写：保持当前 assistant 身份，新增 generation attempt，向其 blocks 追加；每次 attempt 用量单独计。
- 分支切换只更新选择指针，不删除其他节点；更新用 conversation revision 做乐观锁。
- parent/selectedChild/root 外键只能指向同会话节点。复合外键 + 服务层检查；插入树时可使用可延迟外键。角色交替、无环、selectedChild 真正为 child 需要服务层事务验证，单纯外键不足。
- 初版分支选择按会话共享，因此同一用户多设备选择同步；若以后希望每设备独立选择，单独设计 view state，不改树本身。

索引：conversation(user_id, updated_at DESC, id)、message(conversation_id, created_at, id)、message(conversation_id,parent_id)、attachment(user_id,state)、generation(user_id,created_at)。对 generation 建活动状态的部分唯一索引 `conversation_id WHERE state IN ('pending','streaming','cancel_requested')`，防双标签页并发。

### 5.3 内容块及上下文规则

blocks 使用 JSONB，包含文本、引用、thinking、signature、server_tool_use、web_search_tool_result、web_fetch_tool_result 等当前 UI 需要的字段。保存结构不是“允许客户端提交任意结构”：来自上游的内容由服务端校验/归一化。

**存储完整 ≠ 所有历史原样发给模型**。以现有 `reply.ts` 为兼容基准：

- 正常历史不回传 thinking/signature；续写按规则保留本轮非空思考及签名。
- 文本的引用用于展示，非原样历史输入；相邻与分隔文本的拼接规则保持一致。
- 历史仅保留符合规则的 read_link 调用/结果，缺少有效签名的组合不回传。
- 拒绝、模板提示、错误回复不作为普通可用历史。
- 包含服务端工具、拒绝、客户端工具或模板块的回复不能续写；只有停止/输出上限等符合条件状态可续写。
- `refusal` 后须在权威最终消息中清掉正文/思考，前端也同步清除已显示部分，不能仅显示一条警告。增量检查点和备份策略须遵循同一隐私/安全约束。

把 `applyEvent/settleReply/toRequestMessages/canContinueReply` 抽为纯函数并增加 golden fixtures；不要在改造时“顺便简化”。模型不接受的未知块保留诊断元信息但不能盲目重新发送。

## 6. API 契约

以下是**拟定 API v1**。auth 路由沿用 Better Auth 原契约；业务 JSON 错误统一为 `{error:{code,message,retryable,requestId}}`。字段受 Zod 运行时校验；不暴露上游完整错误正文、凭据或内部堆栈。

| 方法/路径 | 说明 |
| --- | --- |
| `GET /api/v1/me` | 用户公开信息与能力/额度摘要 |
| `GET /api/v1/capabilities` | 允许模型、搜索/附件/语音能力、限制；不是上游任意模型列表 |
| `POST /api/v1/conversations` | 创建会话，201 |
| `GET /api/v1/conversations?cursor=&limit=20` | 游标分页摘要，不返回全部消息 |
| `GET /api/v1/conversations/:id` | 元数据、rootMessageId、revision、活动 generation |
| `PATCH /api/v1/conversations/:id` | 标题及 expectedRevision，冲突 409 |
| `DELETE /api/v1/conversations/:id` | 软删除、禁止后续生成；异步清理附件引用 |
| `GET /api/v1/conversations/:id/messages?cursor=&limit=100` | 所有分支节点的稳定分页，含 nextCursor；客户端拉完或按需取分支后建立树 |
| `PATCH /api/v1/conversations/:id/selection` | parentMessageId + selectedChildId + expectedRevision |
| `POST /api/v1/conversations/:id/generations` | 发送/重生成/续写，返回 SSE |
| `GET /api/v1/generations/:id` | 权威状态和当前消息快照，用于断线后对账 |
| `POST /api/v1/generations/:id/cancel` | 幂等取消；终态直接返回实际终态 |
| `POST /api/v1/attachments` | multipart 上传，返回业务附件 ID |
| `GET /api/v1/attachments/:id/content` | 校验归属后的原件代理（启用原件存储时） |
| `DELETE /api/v1/attachments/:id` | 校验引用，进入安全清理流程 |
| `POST /api/v1/speech/transcriptions` | ASR multipart；限制音频大小/时长 |
| `POST /api/v1/speech/synthesis` | TTS PCM 流；返回格式头和能力信息，不包装 SSE |
| `GET /api/v1/usage?from=&to=` | 本人使用量摘要，限制范围 |

发送示例（Idempotency-Key 为随机客户端请求标识，不是 API Key）：

```http
POST /api/v1/conversations/conv-id/generations
Content-Type: application/json
Accept: text/event-stream
Idempotency-Key: 生成一次请求时创建的UUID
```

```json
{
  "operation": "send",
  "expectedRevision": 12,
  "parentMessageId": "上一条assistant-id或null",
  "input": {"text": "解释一下 SSE", "attachmentIds": []},
  "options": {"model": "deepseek-flash", "thinking": true, "search": false}
}
```

`regenerate` 改为提交 `targetUserMessageId`，不重复上传 user 消息；`continue` 提交 `targetAssistantMessageId`，服务端重新验证续写条件。编辑发送增加 `editOfUserMessageId`，服务端从旧节点计算父节点，不信任客户端任意覆盖。

历史 DTO 保留原 UI 消息形状，补充 generationId/version；内部表字段不直接全量暴露。首次兼容采用适配器将 ISO 时间转换成原 UI 毫秒。

## 7. SSE、持久化与失败语义

### 7.1 选择自有薄包装，而不是伪装完全透明

因为要携带数据库 ID、幂等状态和“保存成功”，不能仅把上游 Response 原样 pipe。业务 SSE 外层版本为 1，内层仍保留 DeepSeek 原事件，让现有 reducer 继续工作：

```text
event: generation.started
data: {"v":1,"generationId":"g1","userMessageId":"u1","assistantMessageId":"a1","revision":13}

event: provider.event
data: {"v":1,"generationId":"g1","seq":1,"event":{"type":"content_block_delta","index":0,"delta":{"type":"text_delta","text":"你好"}}}

event: generation.completed
data: {"v":1,"generationId":"g1","messageId":"a1","status":"done","persisted":true,"revision":14}
```

这是精简示例，并非完整上游事件顺序；真正 provider 流仍包含 start/stop 与 usage 等。应用错误 `generation.failed`、停止 `generation.cancelled`，均携带稳定 code 和可恢复提示。每个事件可设 SSE `id: generationId:sequence`，但第一版**不承诺 Last-Event-ID 回放**，只能用于去重和诊断。

前端沿用 POST fetch/ReadableStream，不换为无法提交该 POST body 的原生 EventSource。上游 `message_stop` 只表示模型生成结束；等数据库提交成功，才发业务 completed。若浏览器错过 completed，则 GET generation 对账，不能重发生成。

### 7.2 一次生成的事务边界

1. 认证、归属、输入/模型能力、额度检查。
2. 短事务锁会话行，核对 revision；占用活动任务唯一约束，创建 user/assistant/generation，预留调用额度，提交。
3. 事务外加载受控分支上下文并请求上游；禁止持有数据库事务等待整个模型回复。
4. 顺序消费上游事件，同时更新内存 reducer、向前端发送事件；按时间/字节阈值（建议 1 秒或 16 KB）保存检查点，不每 token UPDATE。
5. 收到 message_stop 后短事务保存最终 blocks、状态、usage、会话 revision/title；提交后业务 completed。自动标题仅在 title_source 非 manual 时更新，避免覆盖用户重命名。
6. 失败/取消进入明确终态，保留允许保留的部分内容与错误代码，释放预留；usage 缺失标记 unknown/partial，绝不伪记为 0。

建议 generation 状态：pending → streaming → succeeded / cancelled / failed / interrupted；cancel_requested 为活动过渡状态。message UI 可映射 done/stopped/error，但服务端保留真实终态原因。

### 7.3 幂等、并发、取消

- 唯一 `(user_id,idempotency_key)` + 请求规范化 hash。相同 key 不同 body 返回 409；相同请求返回已有 generation 状态引用，不再次调用模型，也不谎称能重放原流。
- 同会话生成期间禁止编辑、删除、改选分支或启动第二次生成，返回 409 并提示先停止；最终删除可先请求取消再执行。
- 取消按钮同时调用 cancel API 并 AbortController 取消 fetch。cancel API 和流断开均向上游 AbortController 传播。
- Vercel 上 cancel 请求可能落到另一实例，因此活动 registry 仅可作局部加速，不能作为正确性依据。数据库保存 cancel_requested/lease；运行中的流定期读取取消状态并触发自身上游 AbortController，流断开信号也直接取消。轮询与 heartbeat 共用可清理定时器，只在请求生命周期内运行。不能只写 DB 状态却继续烧费。
- 完成与取消竞争由条件 UPDATE/事务状态机决定；终态只落一次。取消不保证供应商立即停止计费，已生成部分可能收费。
- 页面刷新/断开触发取消；函数回收或超时后 lease 过期，由受保护的 Vercel 定时维护请求或后续业务请求的有界对账标记 interrupted，保留最近检查点。不能依赖常驻启动扫描或无限后台循环。第一版不自动续跑、不自动重新调用付费模型。

### 7.4 错误、背压与连接配置

HTTP 头发出前使用 400/401/403/404/409/413/429/502/504；上游服务商 401 不等于用户登录失效，应映射服务端配置错误，不把用户踢出登录。流开始后不能更改 HTTP 状态，发送业务错误事件并落库；Hono 流回调自身需捕获错误，不能只依赖全局 onError。[Hono Streaming](https://hono.dev/docs/helpers/streaming)

设置 `text/event-stream`、`Cache-Control: no-cache, no-transform`，反向代理关闭 buffering/压缩聚合，合理读超时；定时 heartbeat 保活，但 heartbeat 不是模型进展。分开控制连接超时、无模型进度超时、总生成时长；await 写操作处理背压。UTF-8 与 SSE 帧可跨 chunk，解析要容错未知事件但不能把未收到 message_stop 的关闭当成功。DeepSeek Messages 不用 `[DONE]`。[协议文档](https://api-docs.deepseek.com/guides/anthropic_api/)

## 8. 附件、搜索、语音

### 8.1 仅使用 DeepSeek Files API

PostgreSQL 保存元数据，不存大 Blob/base64。模型 remote_file_id 只在服务端保存，浏览器引用业务 attachmentId。服务端上传、引用、删除均核对归属；文件不能因多个消息共用就被一次会话删除清掉。

**用户已确定**：沿用 DeepSeek Files API，不引入 R2 或 Neon Object Storage。PostgreSQL 仅保存业务附件元数据、归属、状态及服务端专用 provider file_id；浏览器只持有 attachmentId。供应商不支持原件或解析结果下载，因此跨设备只提供元数据/引用，不承诺原件下载、完整预览、补传或完整备份。本次新选择的文件可在当前页面内做临时预览，离页后释放，不读取或迁移旧 IndexedDB 原件。

上传：检查大小、MIME/实际类型、数量、用户配额，随机 storage key，限制 multipart 内存占用，服务端流式转发；不接受客户端任意 remote_file_id。原件与供应商上传之间采用 pending/uploaded/failed 状态及补偿，避免半成功不可见。远端删除以 cleanup job 重试，不在删除会话事务内等待网络。只有所有有效引用解除、保留期满足后才允许进入清理候选。当前删除仅做可恢复状态变更；未得到具体永久删除授权前，不调用供应商 DELETE，也不永久删除业务记录。

最新官方文档已确认 Messages 支持 image/document 文件引用，均由后端附带 `anthropic-beta: files-api-2025-04-14`。上传文档时 purpose 字段必须先于 file；PDF 使用 rich_layout_recognition，UTF-8 文本使用 user_data，图片不发送 purpose。首版只支持 PNG/JPEG/GIF/WebP/PDF 和明确白名单 UTF-8 文本，不因旧前端存在 Office/电子书扩展名就未经安全校验放行。单文件 8 MiB、每消息 10 个、每用户 100 个且 100 MiB；整个请求历史的重复文档引用也计入供应商 20 文档上限。JSON 上下文字节预算不代表已经覆盖供应商展开的文件内容。上传断开仍可能继续解析、保存并计费，结果未知时不自动重试。

### 8.2 搜索/读链接

保留 DeepSeek 服务端工具及引用渲染；用户只能传 search 开关，不允许任意 tools JSON。保留工具块与签名，按原上下文规则回传。不能把来源链接、工具结果 HTML 当可信 UI；链接协议白名单、外链安全属性、避免任意 HTML 注入。

### 8.3 语音

ASR/TTS 经后端统一授权和额度，TTS 是二进制 PCM 流，不是 SSE。保留现有 sample rate/声道/位深契约并做播放测试。取消朗读应取消上游；录音需要浏览器用户权限，测试不擅自打开麦克风。默认不持久化音频，若产品要求保存再增加 retention 和对象存储设计。

## 9. Neon、数据库结构变更与连接管理

Hono 在 Vercel Node.js Functions 使用 `pg.Pool + Drizzle`，模块作用域复用连接池，并接入 `@vercel/functions` 的 `attachDatabasePool` 管理挂起前空闲连接；本地同样复用 Pool。每次 query/transaction 用后释放 client，不每个请求新建 Pool、不每个请求 pool.end()；模型 streaming 不持续占用数据库连接。应用 `DATABASE_URL` 用 pooled endpoint，迁移 `DATABASE_URL_UNPOOLED` 用 direct，均保留 TLS 校验。不要使用 transaction-pooling 不可靠的 session-level 状态。[Neon 连接池](https://neon.com/docs/connect/connection-pooling)

Neon 项目 `deepseek-chat-demo` 已创建，当前开发仅使用已建立的 `dev` 分支，`main` 保持原样。未来 production、测试/PR branch 的环境隔离需在恢复发布工作后落实，不代表这些分支已全部存在。迁移先在隔离 branch 验证，再审批进入生产；schema-only 或脱敏样本优先，避免把生产用户/会话带入开发。分支复制不自动解决模型 Key、认证 Secret 和业务数据隔离；每环境独立配置。[Neon Branching](https://neon.com/docs/introduction/branching)

迁移 SQL 进版本库，review 表/索引/约束及锁影响；不在所有应用副本启动时自动执行迁移。首次执行空库建表；后续 schema 演进采用 expand → deploy → contract，后续删列另行授权和备份。本方案不安排存量聊天 backfill。应用 DB 角色不拥有迁移权限。数据库短暂不可用时只重试安全读或明确幂等写，不重试模型生成。

本次不使用 pgvector/RAG、不引入 Redis、消息队列或 Neon Realtime。跨设备刷新与重新进入会话即可同步；若后续需要多个设备实时观测同一生成，需另加 durable event log/pubsub，不把普通数据库轮询包装成完整恢复流。

## 10. 新数据起步与本地缓存边界

本次不考虑存量数据迁移，不建设旧浏览器历史/ZIP 导入 UI、接口、任务、映射表、附件补传和迁移测试。新用户登录后从空的服务端会话列表开始，仅新系统创建的会话、消息、附件和用量进入 Neon。

旧 IndexedDB、localStorage、原附件及 API Key 保持原状，不读取、不上传、不删除，也不把旧数据作为新系统回滚来源。新版本使用独立、按用户隔离的缓存命名空间，避免新初始化逻辑覆盖旧库。模型 Key 通过服务端安全配置提供，不从旧浏览器数据提取。

新系统离线时可显示本用户的新缓存，生成按钮提示需联网；不实现双向离线写合并。账户 A 缓存不能被 B 看见。

### 11.1 Vercel 项目与构建路由

未来计划在同一 Vercel 项目部署前后端，项目名为 `deepseek-chat-demo`（项目已创建并连接 GitHub，部署当前暂停）。前端保留 Rspack，构建输出静态资源；后端导出 Hono app 的平台兼容入口，不把 `@hono/node-server` 的本地监听过程当作生产启动命令。采用 Vercel 的 Hono 支持及构建配置，实施时验证最终 Function entrypoint、静态产物目录和 rewrite 顺序：`/api/auth/*` 与 `/api/v1/*` 先进入函数，其他前端路由再走 SPA fallback，不能把 API 404 改写成 index.html。不为部署而迁移 Next.js。

Vercel 官方 Hono 集成支持 streaming，静态资产由 CDN 提供；不要依赖 Hono `serveStatic()` 在该集成内服务文件。需用真实 Preview 验证 Rspack + Hono 混合构建，不能假定纯 Hono 零配置会自动理解当前 workspace 布局。[Hono on Vercel](https://vercel.com/docs/frameworks/backend/hono)

### 11.2 SSE 时限与断线收尾

`maxDuration` 覆盖整个调用及等待流式响应的时间，发送 heartbeat 不能绕过它。2026-11-14 查询官方页面：Fluid compute 的 Hobby 上限 300 秒；Pro/Enterprise 可配置更长，超过 800 秒的扩展时限仍为 beta，当前可到 1800 秒。**本方案不假定用户套餐或 beta 资格**：初版建议平台 300 秒、应用总生成预算不超过 270 秒，为最终数据库写入与终态事件留余量；若长思考经常超时，再依据实际套餐明确调整。以部署时平台限制和配置验证为准。[时限配置](https://vercel.com/docs/functions/configuring-functions/duration)

到应用截止时间先主动中止上游、保存允许的部分内容、标记 interrupted/timeout 并返回业务终态。平台硬超时可能来不及发送错误或最终落库，须依赖检查点、lease 与后续对账；不能承诺 finally 必定执行。若需求升级为断线后持续执行或超过函数上限，应另立 durable workflow/队列设计，不在本次默认加入。

针对实际 SSE Function 路径配置 `supportsCancellation: true`，验证浏览器取消能传到 Request.signal/Hono onAbort。断开后的必要短收尾用 Vercel `waitUntil` 注册，但它不是无限后台执行或持久化保证；仍受生命周期/时限约束。不要对所有未适配路由盲开 cancellation。cancel API 的跨实例通知继续遵循 7.3 的数据库状态机制。[请求取消](https://vercel.com/docs/functions/functions-api-reference)

### 11.3 Neon 区域、环境与连接

现有 Neon 项目 `deepseek-chat-demo` 已使用 AWS Singapore `aws-ap-southeast-1`；未来 Vercel Functions 建议 `sin1`，以函数贴近数据库为原则，恢复部署时再核实平台可用性与延迟。不能认为 CDN 离用户近就等于数据库查询近，也不依赖 Vercel 默认区域。[Vercel regions](https://vercel.com/docs/regions)

| 运行环境 | Neon 目标 | 认证/模型配置 |
| --- | --- | --- |
| 本地 8095/8096 | `dev` branch | 开发 Secret、localhost origin、开发模型额度 |
| Vercel Preview | PR 隔离 branch 或明确的预览 branch | 独立 Secret、精确预览 origin、测试模型额度 |
| Vercel Production | production branch | 独立生产 Secret、正式域名、生产模型额度 |

不得让 Preview 或本地指向生产数据库、复用生产 auth Secret、给不可信 PR 注入生产模型 Key。每环境 `DATABASE_URL` 都指向对应 branch 的 pooled endpoint；`DATABASE_URL_UNPOOLED` 只给受控迁移步骤，不注入浏览器或普通运行时。使用模块 Pool + `attachDatabasePool`，连接池大小结合 Fluid 实例并发与 Neon 总连接预算压测，不用全局单连接串行化所有 SSE。[Vercel connection pooling](https://vercel.com/kb/guide/connection-pooling-with-functions)

### 11.4 Better Auth 同源与发布迁移

自托管 Better Auth 仍挂在同一个 Vercel `/api/auth/*`，不因“用 Neon 数据库”自动变成 Neon Auth。`BETTER_AUTH_URL`/`APP_ORIGIN` 在 Production 配正式 HTTPS origin，在 Preview 配明确允许的预览 origin；trustedOrigins 只允许实际需要的域，不能为方便加入任意 `*.vercel.app`。邮箱验证、找回密码和 OAuth 已取消，不配置其回调或邮件链接。`BETTER_AUTH_SECRET` 每环境安全生成并稳定保存，不随 build 随机重生成；轮换另做会话兼容方案。生产启用安全 Cookie，不把 Secret 写入 Rspack 前端变量。

迁移以 Drizzle SQL 为唯一入口：先针对 `dev`/Preview branch 验证，再在受控 release 步骤使用生产 direct URL 执行向后兼容迁移，验证后发布生产应用。不要在每次函数冷启动、每个 Preview build 或所有副本中自动迁移生产。Vercel 代码回滚不会回滚数据库；继续使用 expand/contract 与可验证恢复策略。

### 11.5 上传、清理任务及上线验证

Vercel Functions 有请求体限制，不能因为后端代码“流式处理 multipart”就绕过平台入口上限。当前官方上限说明为 4.5 MB；后端上传接口应留协议开销并设置更小业务上限。当前用户选择不引入对象存储，恢复部署时应缩小上传上限或单独确定其他受控上传架构，不能默认改成 R2/对象存储直传，也不能向浏览器暴露供应商密钥。供应商补传与 TTS 流也需受总时长与资源限制约束。[Functions limits](https://vercel.com/docs/functions/limitations)

cleanup/stale lease 对账采用受鉴权的 Vercel Cron 路由或用户请求时有界修复，不使用常驻 setInterval 期待实例永远存活；定时任务可重复、可能延迟，DB 抢占/幂等必需。Cron 周期按实际套餐确认，快速恢复不能只依赖低频 Cron。

发布前真实 Preview 额外验证：构建静态资源与 API 路由；登录/退出/会话恢复；长 SSE 与心跳；应用截止和平台超时；停止按钮、关闭页面、断网与跨实例 cancel；超时后刷新、函数回收后对账；大上传拒绝；Neon 冷启动与连接池；Preview/Production 数据和凭据隔离。仅 `pnpm build` 成功不足以认定 Vercel 可用。


## 12. 限流、成本与可观测性

公网前必做：注册防滥用、登录限流、按用户+IP 请求频率、用户活动生成上限、每日调用/token 预算、附件/音频容量限制。IP 只信任已配置反向代理，不任意采信 X-Forwarded-For。

首期用户额度在 PostgreSQL 中通过短事务原子预留/结算。不能仅靠实例内 Map 限流来保证多实例成本上限。usage_record 按 generation 唯一，初始与最终累计 usage 不叠加；续写多个 attempt 分开记账。费用如展示，标明估算价格版本，不把估算当供应商最终账单。断流缺失用量以未知表示，并保守处理预留。

指标：鉴权失败率、首事件时延、生成成功率、取消延迟、异常断流率、DB checkpoint 延迟、活动任务过期数、供应商 429/5xx、附件清理积压。告警不能包含用户聊天正文。

### 13.1 必需测试矩阵

- 单元：UTF-8 分片、多行 SSE data、CRLF、空注释、未知事件、无 message_stop、流内 error、顺序 index、签名拼接、refusal 清理、工具/模板续写禁止。
- 树：编辑旧节点不破坏后代、重生成兄弟关系、跨会话 parent 拒绝、环拒绝、空会话/根节点约束、分页后选中路径一致。
- 集成：事务回滚、活动唯一索引、同 key 同 body/异 body、先完成后取消、先取消后完成、重启 stale lease、最终 DB 失败不发 completed。
- Auth：401、账户切换、CSRF、Cookie 属性、会话过期/吊销、跨用户会话/附件/usage 访问 404。
- 浏览器：登录→发送→停止→刷新→再发；编辑/重生成/分支切换；长思考；网络断开；退出时生成；双标签页。
- 供应商：mock 故障先跑，少量真实 DeepSeek 验证文本/思考/搜索/文件/ASR/TTS；不使用用户真实敏感资料，不在测试输出 Key。
- 性能：并发 SSE 不长期占 DB 连接、慢客户端不无限积压、较大历史分页/上下文预算、附件流内存受限。

## 14. 风险、回滚与后续配置确认

风险：SSE 解析语义变动导致思考/引用丢失；将全树当线性历史；重复调用重复计费；全局 Key 下文件越权；浏览器部分输出快于 DB 最终提交；新 Auth 登录与空会话初始状态需明确展示。

回滚以新业务系统的前一兼容构建与功能开关为主，不恢复旧匿名直连模式，也不依赖旧浏览器存量数据。新 schema 先兼容扩展，不破坏性降级数据库；新系统的 DB 使用可验证备份/恢复方案，外部文件删除需延迟。

当前本地文本开发无需新增第三方配置；后续功能与公网发布仍需以下配置或决定：

1. **认证模式**：本地已采用自托管 Better Auth；Neon Auth 不是当前待办。认证安全验收仍未完成；邮箱验证、找回密码和 OAuth 不在范围内。
2. **Neon 目标已落实**：项目 `deepseek-chat-demo`、个人组织、AWS 新加坡、Free；本地使用 `dev`。连接配置已在被 Git 忽略的本地环境文件中，不在文档记录值；生产配置未来单独处理。
3. **登录范围已确定**：仅邮箱密码；P2-05/P2-06 已取消，不做邮箱验证、找回密码、Google/GitHub OAuth，不需要相关邮件或第三方登录配置。
4. **附件原件**：已确定仅使用 DeepSeek Files API，不启用 R2/Neon Object Storage；跨设备原件预览、下载与完整备份明确不支持。
5. **服务端模型 Key 与公网额度**：本地模型配置与真实文本联调已完成；公网模型白名单、预算和生产 Secret 隔离仍待落实。不搬运浏览器 Key。
