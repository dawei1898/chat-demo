# P1 连接池与负载验证

日期：2026-11-14。仅 Neon `deepseek-chat-demo` 的 `dev` 分支，端点已通过 Neon 元数据核验。未使用 main，未调用真实模型、未读取输出凭据。

## 可重复脚本

```sh
node --import tsx server/tests/pool-load-smoke.ts
```

脚本明确限制当前 dev endpoint，使用既有 `local-test-*` 测试用户。所有模型请求被进程内 mock 拦截；三条测试会话保留在 dev。1000 条消息的临时会话在单事务内构造、读取后 ROLLBACK，不触及已有数据。此脚本是显式集成测试，不随普通单元测试运行。

## 实测结果

- 初次建立数据库连接：1219ms（新应用连接，不等于 Neon 休眠冷启动）。
- 3 路模拟生成等待供应商时，全部数据库连接处于 idle，waitingCount=0：流等待不长期持有连接/事务。
- 同时 20 次会话读取：2435ms；连接数不超过 5。
- 1000 条约 1MB 消息全量读取：16353ms，数据数量正确。
- 结束后连接全部空闲，waitingCount=0；pool.end 正常结束。

## 不应提前认定的范围

这不是生产容量/压力上限验收。大历史虽正确，但全量读取延迟明显偏高，必须在 P3-06 继续按需加载、分页及上下文预算设计，不能据此勾选大历史性能已通过。当前 dev endpoint 为 active，suspend_timeout=0，未擅自修改数据库配置或强制挂起；Neon 真正休眠冷启动尚未测。真实多个用户并发 SSE、慢客户端及外网故障矩阵仍待后续验证。模拟供应商结果只证明连接生命周期与持久化链路，不等于真实供应商吞吐。
