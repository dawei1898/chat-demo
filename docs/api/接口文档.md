## 1. 通用约定

### 1.1 地址、请求头与登录态

| 项目       | 当前约定                                                                      |
| ---------- | ----------------------------------------------------------------------------- |
| 浏览器入口 | `http://localhost:8095`                                                       |
| API 前缀   | `/api`；前端开发服务器代理到 `http://127.0.0.1:8096`                          |
| 后端监听   | 仅 `127.0.0.1`，端口默认 `8096`，可由 `API_PORT` 配置                         |
| 可信来源   | `BETTER_AUTH_URL`，默认 `http://localhost:8095`，须与请求的 `Origin` 完全一致 |
| 登录态     | 同源 Cookie；浏览器请求使用 `credentials: 'same-origin'`                      |
| JSON 请求  | `Content-Type: application/json`；没有字段也应按接口要求发送 `{}`             |
| 文件请求   | `multipart/form-data`；交给浏览器或 curl 自动生成 boundary                    |
| 缓存       | 通常返回 `Cache-Control: no-store`，私有响应不应缓存                          |

所有非 `GET`、`HEAD`、`OPTIONS` 请求必须携带正确的 `Origin`，包括创建、更新、上传、取消和删除。缺少或不匹配时返回 `403`。同一环境不要混用 `localhost` 与 `127.0.0.1` 作为前端来源。

本文列出的接口中，`GET /api/health` 无需登录，其余业务接口均要求有效登录态，否则返回 `401`。不接收浏览器提交的用户归属或供应商密钥，也不提供业务 Bearer Token 认证。

### 1.2 参数、时间与大小

- 路径中的 `:id` 依接口分别指会话、生成任务或业务附件 ID；消息 ID 与登录会话 ID 是不同概念。
- 业务 DTO 的 `createdAt`、`updatedAt` 以及思考块的事件时间均为 Unix 毫秒数。来源网页时间另见内容块说明。
- 字段标记“可选”表示可以省略，不表示接受 `null`。明确标记可空的字段才接受或返回 `null`。
- 会话创建、更新、删除及生成的 JSON 请求对象均拒绝未知字段。不能提交整棵消息树、完整历史、`userId`、模型密钥或任意上游参数。
- 普通请求体上限为 `128 KiB`。附件上传与 ASR 的文件上限为 `8 MiB`，multipart 总体积上限为 `8 MiB + 16 KiB`；附件上传有独立的有界读取流程。
- `KiB = 1024` 字节，`MiB = 1024 × 1024` 字节。JSON 字符数限制与 UTF-8 请求体字节限制须同时满足。

### 1.3 错误与状态码

业务接口通常返回以下结构，`code` 可省略：

```json
{
  "error": {
    "message": "会话已在其他窗口更新，请刷新后重试",
    "code": "REVISION_CONFLICT"
  }
}
```

| HTTP 状态 | 含义或常见触发条件                                          |
| --------- | ----------------------------------------------------------- |
| `200`     | 查询或更新成功；生成幂等重放；已就绪附件重放                |
| `201`     | 创建会话成功；首次附件上传成功                              |
| `204`     | 删除会话成功，无响应体                                      |
| `400`     | 字段校验失败、分页参数无效、操作不适用或文件/音频格式不支持 |
| `401`     | 未登录或会话过期                                            |
| `403`     | 请求来源不允许                                              |
| `404`     | 资源不存在、不属于当前用户或会话已删除                      |
| `408`     | 附件请求体读取超时                                          |
| `409`     | 版本、生成并发、幂等、分支或附件状态冲突                    |
| `413`     | 请求体、附件、上下文或上下文附件预算超限                    |
| `429`     | 请求频率、并发或附件配额限制                                |
| `500`     | 未分类的服务端异常                                          |
| `502`     | 附件或语音上游失败、响应无效或结果不能确认                  |
| `503`     | 后端未配置所需供应商能力                                    |

部分 `429` 响应带 `Retry-After`，单位为秒；并非所有限流响应都提供此头。未匹配路由可能由框架直接返回文本 `404`，不能假设所有错误都是 JSON。当前业务路由对非法 JSON 解析异常未统一映射为 `400`，可能返回通用 `500`；应发送合法 JSON。

资源归属从登录态确定，访问其他用户资源通常表现为 `404`。SSE 或音频响应开始后发生的错误，不会改成新的 HTTP 错误状态，具体见生成与语音章节。

## 3. 公共数据结构

### 3.1 会话摘要与完整会话

`SessionSummary` 是列表元素：

| 字段        | 类型    | 说明                                             |
| ----------- | ------- | ------------------------------------------------ |
| `id`        | string  | 会话 ID                                          |
| `title`     | string  | 标题；空字符串表示尚无标题                       |
| `revision`  | integer | 当前服务端版本；写操作的 `expectedRevision` 来源 |
| `createdAt` | number  | 创建时间，毫秒                                   |
| `updatedAt` | number  | 最近更新时间，毫秒                               |

完整 `Session` 在上述字段外包含：

| 字段            | 类型           | 说明                                                           |
| --------------- | -------------- | -------------------------------------------------------------- |
| `rootMessageId` | string 或 null | 当前选中的根消息；空会话为 `null`                              |
| `messages`      | Message[]      | 全部消息节点，包含未选中的历史版本；数组顺序不代表当前可见路径 |

从 `rootMessageId` 开始，沿消息的 `selectedChildId` 遍历，得到当前分支。`parentId` 相同的消息互为版本。编辑与重新生成会保留原版本和后续分支。

```json
{
  "id": "11111111-1111-4111-8111-111111111111",
  "title": "",
  "revision": 0,
  "createdAt": 1794614400000,
  "updatedAt": 1794614400000,
  "rootMessageId": null,
  "messages": []
}
```

### 3.2 分支视图

`view=branch` 返回的 `Session` 还包含以下字段，并改变 `messages` 的含义：

| 字段         | 类型              | 说明                                                   |
| ------------ | ----------------- | ------------------------------------------------------ |
| `view`       | `"branch"`        | 明确标记部分正文视图                                   |
| `messages`   | Message[]         | 当前分支的一个正文窗口，最多 50 条，按路径从旧到新排列 |
| `treeIndex`  | SessionTreeNode[] | 全树导航索引，含所有版本，不含正文                     |
| `hasEarlier` | boolean           | 当前窗口前是否还有正文                                 |
| `beforeId`   | string 或 null    | 当前窗口首条消息 ID，供向前分页；空窗口为 `null`       |

`SessionTreeNode` 包含 `id: string`、`parentId: string | null`、可选 `selectedChildId: string`、`role: "user" | "assistant"`、`createdAt: number`。

分支视图不是完整消息树，不能把窗口内的 `messages` 当成全量历史。本后端没有“客户端整树写回”接口。

### 3.3 消息

两种消息都包含 `id: string`、`role`、`createdAt: number`；分支关系包含 `parentId`（string 或 null，兼容类型可省略）和可选 `selectedChildId: string`。

| 用户消息字段 | 类型             | 必有 | 说明                          |
| ------------ | ---------------- | ---- | ----------------------------- |
| `role`       | `"user"`         | 是   | 用户消息                      |
| `content`    | string           | 是   | 文本，纯附件消息可为空字符串  |
| `files`      | FileAttachment[] | 是   | 业务附件元数据，无附件为 `[]` |

| 助手消息字段         | 类型           | 必有 | 说明                                                                                  |
| -------------------- | -------------- | ---- | ------------------------------------------------------------------------------------- |
| `role`               | `"assistant"`  | 是   | 助手消息                                                                              |
| `model`              | string 或 null | 是   | 当前业务生成固定 `deepseek-flash`；共享类型也兼容 `deepseek-v4-pro`，请求不能指定模型 |
| `thinking`、`search` | boolean        | 否   | 本轮思考 / 搜索开关快照                                                               |
| `latestReminder`     | string         | 否   | 上下文提醒快照；生成请求不允许客户端直接提交                                          |
| `prefix`             | boolean        | 是   | 允许作为续写前缀的标记；仍须满足续写条件                                              |
| `status`             | string         | 是   | `pending`、`streaming`、`done`、`stopped`、`error`                                    |
| `blocks`             | ReplyBlock[]   | 是   | 按顺序排列的内容块                                                                    |
| `stopReason`         | string         | 否   | `end_turn`、`max_tokens`、`tool_use`、`refusal`                                       |
| `stopDetails`        | object         | 否   | 拒绝详情：`{type:"refusal", category:null, explanation:null}`                         |
| `usage`              | MessageUsage   | 否   | 最近一次请求用量，续写后更新；缺失不表示消耗为零                                      |
| `error`              | object         | 否   | 至少含 `kind`、`message`；可带 `status`、`localMessage`、`retryable` 等兼容字段       |

`pending` 表示等待生成数据，`streaming` 表示接收中，`done` 表示正常结束，`stopped` 表示停止或中断恢复，`error` 表示失败。消息状态与生成任务状态分开理解：任务还可能是 `running` 或 `interrupted`。

业务生成持久化的错误通常为 `{kind:"stream", message:"安全错误文案"}`。共享类型中 `kind` 还兼容 `http`、`network`、`interrupted`、`protocol`、`upload`；不要依赖任意上游原文。

### 3.4 内容块与用量

| `type`                   | 字段                                                                                                           | 说明                                   |
| ------------------------ | -------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| `text`                   | `text: string`；可选 `citations: TextCitation[]`、`isTemplate: boolean`                                        | 正文；模板提示不参与历史上下文或续写   |
| `thinking`               | `thinking: string`；可选 `signature: string`、`startedAt: number`、`endedAt: number`、`elapsedSeconds: number` | 思考内容；事件时间为毫秒，耗时为秒     |
| `server_tool_use`        | `id`、`name`、`input`、`caller`、`kind`                                                                        | 工具调用，见下文                       |
| `web_search_tool_result` | `tool_use_id: string`、`content: array`、`kind`                                                                | 搜索结果，成功无结果时为 `[]`          |
| `web_fetch_tool_result`  | `tool_use_id: string`、`content: object`、`kind`；可选 `signature: string`                                     | 网页读取结果；签名是不可解读的协议数据 |

`TextCitation` 字段：`type="web_search_result_location"`、`url: string`、`title: string | null`、`cited_text: string`、`encrypted_index: string`（当前为空字符串）。

工具调用 `name` 为 `deepseek_web_search` 或 `deepseek_read_url`，`caller` 为 `{type:"direct"}`。`kind` 为 `search`、`deep_search`、`read_link`、`image_search`、`deep_image_search`。`input` 按动作区分：

- `search`：`{action:"search", queries:string[], query?:string}`。
- `open_page`：`{action:"open_page", url:string}`。
- `find_in_page`：`{action:"find_in_page", url:string, pattern:string}`。
- `read_link`：`{action:"read_link", url:string}`。

搜索结果块的 `kind` 不含 `read_link`。成功结果项包含 `type="web_search_result"`、`title`、`url`、`snippet`、`encrypted_content`（均为 string），`site_icon`、`site_name`、`page_age`（string 或 null）及可选 `image_url: string`。`page_age` 为 RFC 3339 时间；加密内容不能直接解密展示。失败项为 `{type:"web_search_tool_result_error", error_code:"unavailable"}`。

网页结果块的 `kind` 为 `read_link` 或 `deep_search`。成功 `content` 为 `{type:"web_fetch_result", url, published_at, content:{type:"document", source:{type:"text", media_type:"text/plain", data:""}, title}}`：`url` 为 string，`title` 与 `published_at` 可为 null；`read_link` 的发布时间可为原始日期字符串，`deep_search` 为 RFC 3339。失败 `content` 为 `{type:"web_fetch_tool_result_error", error_code}`，错误码为 `url_not_accessible`、`url_not_allowed` 或 `unavailable`。

`MessageUsage` 包含数值字段 `input_tokens`、`cache_creation_input_tokens`、`cache_read_input_tokens`、`output_tokens`，可选 `server_tool_use: {web_search_requests:number, tool_search:number}`。此对象不是账单查询接口，也不代表失败或中断时最终用量一定完整。

以上结构是业务响应中保存的内容块，不是浏览器可以任意提交的工具参数；完整类型见[协议类型](../../src/services/api/types.ts)和[消息类型](../../src/services/chat/types.ts)。

### 3.5 附件元数据

附件接口返回 `AttachmentMetadata`，用户消息的 `files` 也使用这些业务字段：

| 字段           | 类型         | 说明                                                                                       |
| -------------- | ------------ | ------------------------------------------------------------------------------------------ |
| `id`           | string       | 业务附件 UUID，生成请求使用此值                                                            |
| `attachmentId` | string       | 同 `id`；共享消息兼容类型中可省略                                                          |
| `serverId`     | null         | 浏览器始终拿到 `null`，供应商文件 ID 仅后端使用                                            |
| `name`         | string       | 原文件名                                                                                   |
| `size`         | number       | 文件字节数                                                                                 |
| `mimeType`     | string       | 后端验证、规范化后的 MIME                                                                  |
| `isImage`      | boolean      | 是否为支持的图片                                                                           |
| `status`       | string       | `pending`、`ready`、`failed`、`unknown`、`deleted`；附件接口返回，消息共享类型不要求此字段 |
| `errorCode`    | string，可选 | 记录中的状态原因，如 `PROVIDER_REJECTED`、`UPLOAD_UNCONFIRMED`；与 HTTP 错误码分开理解     |

附件查询只返回元数据，不提供原件下载、供应商凭据或供应商文件地址。

## 5. 会话与消息分支

本节所有接口均要求登录。

### 5.1 `GET /api/conversations`

查询当前用户未软删除的会话，按 `updatedAt DESC, id DESC` 排列。响应不含消息正文。

| 查询参数 | 类型                   | 说明                                                 |
| -------- | ---------------------- | ---------------------------------------------------- |
| `limit`  | 十进制整数字符串，可选 | `1`–`100`；不接受 `0`、前导零、小数、空值或重复参数  |
| `cursor` | string，可选           | 上页 `nextCursor` 原样传回；不可为空，不接受重复参数 |

存在两种成功 `200` 契约：

- 不传 `limit` 与 `cursor`：返回 `SessionSummary[]`，最多 200 条，兼容旧调用。
- 传入任一分页参数：返回 `{items:SessionSummary[], nextCursor:string|null}`；仅传 `cursor` 时 `limit` 默认 50。`nextCursor=null` 表示没有下一页。

游标为不透明的 Base64URL 字符串，内部保留数据库微秒精度与 ID 排序边界。客户端只保存并透传，不转换为毫秒或自行构造。列表是游标翻页，不是跨多次请求的冻结快照；翻页期间发生更新时可刷新首页。

主要错误：`400` 分页参数无效、`401` 未登录、`500` 服务异常。读取列表前会尝试恢复当前用户心跳超时的生成。

### 5.2 `POST /api/conversations`

JSON：可选 `title: string`，最多 200；省略时使用空字符串。无标题也需发送 `{}`，不接受其他字段。

成功 `201` 返回完整 `Session`，初始 `revision=0`、`rootMessageId=null`、`messages=[]`。空标题会话可在后续生成中自动获得标题。

主要错误：`400` 参数校验失败，另见公共错误。

### 5.3 `GET /api/conversations/:id`

路径 `id` 为会话 ID。默认 `200` 返回完整 `Session`。查询参数：

| 参数       | 类型         | 说明                                                                      |
| ---------- | ------------ | ------------------------------------------------------------------------- |
| `view`     | string，可选 | 精确为 `branch` 时返回分支视图；省略或其他值走完整树                      |
| `beforeId` | string，可选 | 仅 `view=branch` 时生效；取当前分支中该消息之前的最多 50 条，不含锚点本身 |

首次分支请求不传 `beforeId`，获取末尾窗口。若 `hasEarlier=true`，把响应 `beforeId` 带入下一次请求并把旧窗口前插。当前选中分支改变后重新从末尾加载，不复用旧分支游标。

主要错误：`404` 会话不存在、已删除或不属于当前用户；非空历史锚点不在当前分支返回 `400 / INVALID_MESSAGE_CURSOR`。读取前会尝试恢复超时生成。

### 5.4 `PATCH /api/conversations/:id`

支持重命名和切换当前消息版本。JSON：

| 字段                | 类型             | 必填 | 说明                    |
| ------------------- | ---------------- | ---- | ----------------------- |
| `expectedRevision`  | integer，≥ 0     | 是   | 最近服务端返回的版本    |
| `title`             | string，最多 200 | 否   | 新标题，可为空字符串    |
| `selectedMessageId` | string，最多 128 | 否   | 要选择的现有消息版本 ID |

成功 `200` 返回更新后的完整 `Session`；加 `?view=branch` 返回分支视图。只传 `expectedRevision` 也会保存并递增版本。

版本切换仅对当前可见路径上节点的兄弟版本生效，恢复目标版本原先选中的后续路径。若消息存在但不属于可切换位置，当前实现可能保持路径不变并正常返回，不能把所有无效切换都理解为 `400`。

主要错误：`400` 参数错误、`404` 会话或消息不存在、`409 / REVISION_CONFLICT` 版本过期、`409` 会话仍在生成。

### 5.5 `DELETE /api/conversations/:id`

必须发送 JSON：`{expectedRevision:integer}`，值 ≥ 0。成功 `204`，无响应体。仅软删除会话，不是批量清理供应商附件。

生成中的会话必须先取消并等待收尾。主要错误：`400`、`404`、`409 / REVISION_CONFLICT`、`409` 仍在生成。

### 5.6 乐观锁与冲突处理

会话更新、删除、发起生成均要求 `expectedRevision`。版本以服务端最新响应为准，不应在客户端假设每次只增加 1；生成准备、终态与中断恢复都可能更新版本。

遇到 `REVISION_CONFLICT`，重新获取会话并让用户操作基于最新状态重试。不要只替换版本号就盲目重放旧编辑或发送内容。已发出的同一生成请求若仅做网络重试，应保持原幂等键及原请求字段，见下一节。

## 6. 生成与取消

### 6.1 `POST /api/conversations/:id/generations`

要求登录，路径 `id` 为会话 ID。可选 `?view=branch` 控制流中 `session` 的形状；只影响返回视图，后端始终加载完整权威历史。

JSON 参数：

| 字段               | 类型                     | 必填   | 默认与约束                                                   |
| ------------------ | ------------------------ | ------ | ------------------------------------------------------------ |
| `expectedRevision` | integer，≥ 0             | 是     | 当前会话版本                                                 |
| `operation`        | string                   | 是     | `send`、`edit`、`regenerate`、`continue`                     |
| `idempotencyKey`   | string，8–128            | 是     | 本次逻辑操作的唯一标识，建议 UUID                            |
| `content`          | string                   | 按操作 | 先 trim，最多 32000；见操作表                                |
| `attachmentIds`    | string[]                 | 否     | 最多 10 个业务附件 UUID，只接受当前用户未删除的 `ready` 附件 |
| `messageId`        | string，最多 128         | 按操作 | 编辑 / 重新生成 / 续写的当前分支目标消息                     |
| `parentId`         | string 或 null，最多 128 | 否     | `send` 时用于校验当前分支末节点；空分支为 `null`             |
| `thinking`         | boolean                  | 否     | 默认 false；创建新回答时的思考开关                           |
| `search`           | boolean                  | 否     | 默认 false；创建新回答时的联网搜索开关                       |

| 操作         | 目标与输入                                                  | 行为                                                                                                      |
| ------------ | ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `send`       | `content` 非空或存在附件；`parentId` 若传入须匹配当前末节点 | 在当前选中分支末尾添加用户消息与助手回答；末节点为用户消息时拒绝                                          |
| `edit`       | `messageId` 为当前分支用户消息；新文本或有效附件非空        | 新建用户版本及回答，保留原消息；省略 `attachmentIds` 保留原附件，传 `[]` 清空附件；省略文本时按空文本处理 |
| `regenerate` | `messageId` 为当前分支助手回答，前一条必须为用户消息        | 为同一提问新建助手兄弟版本；沿用该提问及附件                                                              |
| `continue`   | `messageId` 为当前分支最后的助手回答                        | 追加到同一回答；沿用原回答的思考 / 搜索快照                                                               |

`regenerate`、`continue` 不允许传 `attachmentIds`，即使为 `[]` 也拒绝。续写要求 `prefix=true`，且为 `stopped` 或 `done + max_tokens`；拒绝、客户端工具调用、含任意服务端工具调用/结果、含模板提示的回答不可续写。失败回答不能续写。

当前模型固定 `deepseek-flash`。`search=false` 时仍启用阅读链接能力，不能据此认为完全禁止网页读取。历史由后端根据当前分支组装，失败、无可用正文、拒绝及模板提示不作为正常历史回答回传。

### 6.2 幂等与双响应类型

同一用户的 `idempotencyKey` 跨会话唯一。请求指纹包含会话、操作、文本、目标、父节点、两个开关、`expectedRevision` 及附件列表。复用键时必须保持这些字段一致；省略附件列表与传空列表也可能被视为不同请求。

- 新请求：先完成校验与任务预建，再返回 `200 text/event-stream`，附 `X-Accel-Buffering: no`。
- 已存在的相同请求：返回 `200 application/json`，不再次请求模型，也不重新接续原 SSE。

重放响应示例：

```json
{
  "replay": true,
  "runId": "44444444-4444-4444-8444-444444444444",
  "status": "done",
  "conversationId": "11111111-1111-4111-8111-111111111111"
}
```

任务 `status` 可能为 `running`、`done`、`stopped`、`error`、`interrupted`。重放不带 `session`，需要重新获取会话；不存在单独的任务查询或 SSE 重连接口。

客户端应先检查 HTTP 状态及 `Content-Type`，再选择 JSON 或 SSE 解析。相同键不同内容返回 `409 / IDEMPOTENCY_CONFLICT`；旧任务缺少可验证指纹返回 `409 / IDEMPOTENCY_LEGACY_UNKNOWN`。改版本后发起新的用户操作须使用新键；键冲突不应通过自动换键触发重复计费。

### 6.3 SSE 事件

这是业务快照流，不直接透传上游内容增量。每帧为 `event: 名称` 与 `data: 单行 JSON`，空行分隔。无 `[DONE]` 结束标记，不提供事件 ID 或 `Last-Event-ID` 恢复契约。使用 POST fetch 读取，不能用只支持 GET 的原生 EventSource 发起本接口。

| 事件       | `data` 字段                                                             | 含义                                                                                    |
| ---------- | ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `snapshot` | `session:Session`、`runId:string`                                       | 当前展示快照；首次包括预建消息，之后包含累计正文；应替换对应快照，不逐帧拼接全文        |
| `done`     | `session:Session`、`runId:string`                                       | 终态事务已提交；包含正常完成或已停止的最终状态，须查看助手 `status`                     |
| `error`    | `runId:string`、`code:string`、`message:string`，可带 `session:Session` | 有 `session` 表示该失败终态已提交；没有表示最终保存或租约有问题，须重新查询最近落库状态 |

`view=branch` 时以上所有携带的 `session` 都转换为最多 50 条正文的分支视图。流中快照可能比最近检查点更新，不代表每帧内容均已保存。只有收到终态 `done`，或携带 `session` 的 `error`，才能按对应终态事务已提交处理。

以下是不携带权威会话快照的保存失败帧示例：

```text
event: error
data: {"runId":"44444444-4444-4444-8444-444444444444","code":"SAVE_FAILED","message":"最终保存失败，请刷新检查最近检查点，不能视为完成"}

```

携带 `session` 的 `snapshot` 与 `done` 完整帧示例见第 9 节。客户端应按 SSE 规则处理跨网络块拆分的行与帧；流关闭或 HTTP `200` 都不能单独证明生成完成。

### 6.4 停止、恢复与错误

每个会话最多一个运行中任务，每用户一分钟内最多新建 10 个生成任务。后端预算：总时长 240 秒、连接 30 秒、无进展 60 秒、单次向客户端写入 10 秒、上游响应总量 4 MiB。这些是服务端限制，浏览器不能覆盖。

最终模型请求的完整 JSON UTF-8 大小上限为 256 KiB，不等同于 Token 数限制，不会静默截断；超限返回 `413 / CONTEXT_BUDGET_EXCEEDED`。`MAX_OUTPUT_TOKENS` 默认 4096，服务端限制在 256–8192 范围内。

在列表、会话详情及生成入口会尝试恢复心跳超过 60 秒的运行中任务：任务标记为 `interrupted`，回答显示为 `stopped` 并保留最近检查点，递增会话版本，不自动再次调用模型。浏览器断开也会触发停止收尾，但客户端仍应重新查询确认保存结果。

生成建立 SSE 前的主要错误：

| 状态 / 代码                                                 | 说明                                                |
| ----------------------------------------------------------- | --------------------------------------------------- |
| `400`                                                       | 无效操作、空消息、无效续写或参数校验失败            |
| `400 / INVALID_ATTACHMENT_OPERATION`                        | 不允许替换附件的操作传入了附件列表                  |
| `401`                                                       | 登录失效                                            |
| `404`                                                       | 会话不存在、目标消息不在当前分支，或附件不可用      |
| `409 / REVISION_CONFLICT`                                   | 会话版本冲突                                        |
| `409 / IDEMPOTENCY_CONFLICT`、`IDEMPOTENCY_LEGACY_UNKNOWN`  | 幂等请求冲突或旧记录不可验证                        |
| `409`                                                       | 已有运行中生成、分支变化、当前分支缺少回答          |
| `413 / CONTEXT_BUDGET_EXCEEDED`、`ATTACHMENT_CONTEXT_LIMIT` | 上下文预算超限                                      |
| `429`                                                       | 生成频率超限                                        |
| `503`                                                       | 未配置 `DEEPSEEK_API_KEY`，当前也会阻止幂等重放入口 |

SSE 建立后的错误码：

| 代码                                               | 含义                           |
| -------------------------------------------------- | ------------------------------ |
| `UPSTREAM_AUTH`                                    | 模型服务认证失败               |
| `UPSTREAM_RATE_LIMIT`                              | 模型服务限流                   |
| `UPSTREAM_UNAVAILABLE`                             | 模型服务不可用                 |
| `STREAM_INTERRUPTED`                               | 上游流提前结束或协议不可用     |
| `TOTAL_TIMEOUT`、`CONNECT_TIMEOUT`、`IDLE_TIMEOUT` | 总时长、连接或无进展超时       |
| `CLIENT_SLOW`                                      | 客户端接收过慢                 |
| `RESPONSE_TOO_LARGE`                               | 模型响应超过安全上限           |
| `DATABASE_UNAVAILABLE`                             | 数据库不可用，刷新核对结果     |
| `LEASE_LOST`                                       | 任务已由其他请求结束或恢复     |
| `SAVE_FAILED`                                      | 最终保存失败，不能显示为已完成 |
| `SESSION_EXPIRED`                                  | 登录会话失效                   |

错误文案经过后端分类，不透传上游正文。不要在未知结果或连接失败时自动换幂等键重发。

### 6.5 `POST /api/generations/:id/cancel`

要求登录；`id` 为 `runId`，无需请求体。成功 `200`：

```json
{ "ok": true, "status": "running", "cancelRequested": true }
```

先持久化取消标记，再尝试中止任务。`status=running` 不表示取消失败，只表示尚未收尾。重复取消可返回已有状态；已完成任务保持原终态，`cancelRequested` 也可能为 false。不存在或不属于当前用户的任务返回 `404`。

取消响应不是最终保存凭据。继续读取原 SSE 终态或重新查询会话，再进行删除、切换分支或下一次生成。

## 7. 附件接口

本节均要求登录，使用业务附件 ID；浏览器不能提交供应商文件 ID。

### 7.1 支持范围与配额

| 文件类别 | 扩展名                                                                         | MIME / 限制                                                                                 |
| -------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| 图片     | `png`、`jpg`、`jpeg`、`gif`、`webp`                                            | 分别为 `image/png`、`image/jpeg`、`image/gif`、`image/webp`；宽高均为 1–4096；拒绝动画 WebP |
| PDF      | `pdf`                                                                          | `application/pdf`；检查 PDF 头尾，使用版面解析能力                                          |
| 文本     | `txt`、`md`、`csv`、`json`、`log`、`js`、`ts`、`py`、`css`、`java`、`go`、`rs` | UTF-8、非空白，拒绝不允许的控制字符；JSON 必须可解析                                        |

文本的规范 MIME：`txt/log/ts/py/java/go/rs` 为 `text/plain`，`md` 为 `text/markdown`，`csv` 为 `text/csv`，`json` 为 `application/json`，`js` 为 `text/javascript`，`css` 为 `text/css`。每种文本也接受 `text/plain`；JS 另接受 `application/javascript`，返回时规范化为对应 MIME。

每个文件非空且最多 8 MiB。文件名 UTF-8 不超过 255 字节，不允许路径分隔符、控制字符。扩展名、MIME 与文件结构须同时通过校验，不能只改后缀；不支持 Word、Excel、PPT、压缩包、SVG、音视频或其他未列出的格式。当前格式校验失败返回 `400 / INVALID_ATTACHMENT`，不是 `415`。

本地限制：

- 每进程最多同时 2 个上传；每用户一分钟内最多新建 10 条上传记录。
- 每用户非 `failed` 记录最多 100 个、总大小最多 100 MiB；`unknown`、软删除记录仍计入，删除不立即释放配额。
- 一次生成最多提交 10 个附件 ID；实际进入上下文的历史与本轮提问合计最多 20 份文档、64 张图片、128 MiB 图片。相同附件重复出现按出现次数计入上下文预算。
- 附件请求体总读取 30 秒，单次等待数据最多 10 秒；转发上传整体预算 180 秒。

### 7.2 `POST /api/attachments`

multipart 仅允许以下两个字段，且各出现一次：

| 字段        | 类型        | 必填 | 说明                          |
| ----------- | ----------- | ---- | ----------------------------- |
| `file`      | File        | 是   | 单个支持的文件，须带正确 MIME |
| `uploadKey` | string UUID | 是   | 本次上传任务的幂等键          |

首次成功 `201` 返回 `AttachmentMetadata` 且 `status=ready`。同用户、同键、同文件名/规范 MIME/大小/内容且既有记录仍就绪时，`200` 返回已有元数据，不重复上传。

同键不同文件返回 `409 / ATTACHMENT_IDEMPOTENCY_CONFLICT`。同键记录尚未就绪、失败、未知或已移除时，不会自动重新上传；返回 `409 / ATTACHMENT_UPLOAD_PENDING` 或 `ATTACHMENT_UPLOAD_UNKNOWN`。

浏览器超时或断开后，供应商可能已经保存文件；后端会继续核对本次上传结果。无法确定时保留 `unknown`，不要换 `uploadKey` 自动重传。

### 7.3 元数据查询

| 接口                                            | 参数                    | 成功响应                 | 主要错误                                       |
| ----------------------------------------------- | ----------------------- | ------------------------ | ---------------------------------------------- |
| `GET /api/attachments/by-upload-key/:uploadKey` | `uploadKey` 必须为 UUID | `200 AttachmentMetadata` | `400` 键格式错误；`404 / ATTACHMENT_NOT_FOUND` |
| `GET /api/attachments/:id`                      | 业务附件 ID             | `200 AttachmentMetadata` | `404 / ATTACHMENT_NOT_FOUND`                   |

两者均无请求体，只查询当前用户记录；可能返回 `pending`、`failed`、`unknown` 或 `deleted` 元数据，不能因 HTTP 成功就把附件视为可用于生成。

### 7.4 `POST /api/attachments/:id/reconcile`

无需请求体。成功 `200` 返回 `ready` 元数据。典型流程：上传响应丢失 → 按原 `uploadKey` 查询 → 若已 `ready` 直接使用 → 否则按业务 ID 调用核对。

- `ready`：直接返回现有结果。
- `pending`：创建未超过 5 分钟时返回 `409 / ATTACHMENT_UPLOAD_PENDING`；超过后可转为 `unknown` 再尝试核对。
- `unknown`：仅在后端已经记录合法供应商 ID 时查询供应商元数据；一致后恢复为 `ready`。
- 缺少可安全核对的引用或为 `failed`：返回 `409 / ATTACHMENT_RECONCILE_MANUAL`，需要人工核对。
- `deleted`：返回 `409 / ATTACHMENT_REMOVED`，不自动恢复。

不会重新上传原件、扫描共享供应商列表，或凭同名文件认领归属。真正进入供应商核对的请求每用户 10 次 / 60 秒，限流带 `Retry-After`。

### 7.5 `DELETE /api/attachments/:id`

无需请求体。成功 `200`：`{"ok":true}`。仅移除未被消息引用、非上传中的附件，标记 `deleted` 与待清理；不保证供应商文件已同步删除，也不立即释放配额。

不存在或非本人返回 `404 / ATTACHMENT_NOT_FOUND`；上传中返回 `409 / ATTACHMENT_UPLOAD_PENDING`；已被任何消息引用返回 `409 / ATTACHMENT_REFERENCED`，包括保留的历史分支引用。

### 7.6 附件错误码

除公共鉴权、来源与服务错误外：

| HTTP / 代码                                                       | 说明                                  |
| ----------------------------------------------------------------- | ------------------------------------- |
| `400 / INVALID_ATTACHMENT`                                        | 表单、文件名、MIME、内容或尺寸不支持  |
| `400`（无 code）                                                  | `uploadKey` 的 Zod 校验失败           |
| `401 / SESSION_EXPIRED`                                           | 读取或核对前再次校验发现登录失效      |
| `408 / ATTACHMENT_BODY_TIMEOUT`                                   | 读取上传请求体超时                    |
| `413 / ATTACHMENT_TOO_LARGE`                                      | 文件或 multipart 过大                 |
| `413 / ATTACHMENT_CONTEXT_LIMIT`                                  | 生成上下文附件预算超限                |
| `404 / ATTACHMENT_NOT_FOUND`                                      | 记录不存在、无权访问或生成引用不可用  |
| `409 / ATTACHMENT_IDEMPOTENCY_CONFLICT`                           | 同上传键对应不同文件                  |
| `409 / ATTACHMENT_UPLOAD_PENDING`、`ATTACHMENT_UPLOAD_UNKNOWN`    | 原上传未能确认可用                    |
| `409 / ATTACHMENT_REMOVED`、`ATTACHMENT_REFERENCED`               | 已移除或仍有消息引用                  |
| `409 / ATTACHMENT_RECONCILE_MANUAL`                               | 不能自动安全核对                      |
| `409 / ATTACHMENT_RECONCILE_MISMATCH`、`ATTACHMENT_STATE_CHANGED` | 元数据不符或核对期间状态变化          |
| `409` 或 `502 / ATTACHMENT_RECONCILE_UNCONFIRMED`                 | 核对结果仍不能确认或核对传输异常      |
| `429 / UPLOAD_BUSY`、`ATTACHMENT_RATE_LIMIT`、`ATTACHMENT_QUOTA`  | 上传并发、频率或配额超限              |
| `429 / ATTACHMENT_RECONCILE_RATE_LIMIT`                           | 核对频率超限                          |
| `429` 或 `502 / ATTACHMENT_PROVIDER_FAILED`                       | 上游明确拒绝，429 原因保留为 HTTP 429 |
| `502 / ATTACHMENT_PROVIDER_INVALID`、`ATTACHMENT_UPLOAD_UNKNOWN`  | 上游响应无效或上传结果不确定          |
| `503 / ATTACHMENT_UNAVAILABLE`                                    | 后端未配置文件服务                    |

## 8. 语音接口

均要求登录，POST 必须带正确 `Origin`，共享每用户每分钟 10 次、同时最多 2 个语音请求的进程内限制。未配置后端 Key 时返回 `503 / SPEECH_NOT_CONFIGURED`；限流返回 `429 / RATE_LIMITED`，不保证有 `Retry-After`。

### 8.1 `POST /api/speech/asr`

multipart 只允许一个 `file` 字段。成功 `200 application/json`：

```json
{ "text": "你好，请帮我整理这段内容。" }
```

输入要求：

- MIME 为 `audio/wav`、`audio/wave` 或 `audio/x-wav`，且内容为合法 RIFF/WAVE。
- PCM16 整数编码，单声道或双声道；采样率为 8000、16000、22050、24000、32000、44100、48000 Hz 之一。
- 仅一个标准 16 字节 `fmt ` 块、一个非空 `data` 块，字节率、对齐和 RIFF 长度一致。
- 时长不超过 120 秒，文件不超过 8 MiB；multipart 总体不超过 `8 MiB + 16 KiB`。
- 不接收 WebM、Opus、MP3 等其他容器，客户端需先转换为支持的 WAV。

非法音频、文件超过单文件上限或表单不合规返回 `400 / INVALID_SPEECH_INPUT`；最外层请求体超限先返回公共 `413`。

### 8.2 `POST /api/speech/tts`

JSON 只允许两个字段，均必填：

| 字段    | 类型   | 说明                                                                                                           |
| ------- | ------ | -------------------------------------------------------------------------------------------------------------- |
| `text`  | string | 非空白文本；汉字每码点计 2，其余每 Unicode 码点计 1，合计不超过 10000；整个解析后 JSON 序列化体积不超过 60 KiB |
| `voice` | string | `stella` 或 `tide`；没有默认声线                                                                               |

后端固定使用 PCM 并开启 Markdown 过滤，不接受浏览器覆盖输出格式或上游参数。

成功 `200`，`Content-Type: application/octet-stream`，返回原始 PCM 字节流：24 kHz、16 位有符号整数、小端、单声道，无 WAV 头。按 2 字节组成采样，网络块不保证恰好对齐采样边界，客户端应缓存跨块的剩余字节；不能直接把响应当 WAV/MP3 文件。

### 8.3 超时、断流与错误

语音请求整体预算 120 秒，上游连接等待 30 秒，响应单次读取等待最多 15 秒。ASR 上游响应最多 256 KiB；TTS 最多 `24000 × 2 × 120` 字节。客户端取消、登录会话撤销或校验失败会终止传输。

| HTTP / 代码                    | 说明                                     |
| ------------------------------ | ---------------------------------------- |
| `400 / INVALID_SPEECH_INPUT`   | 音频或文本参数不合规                     |
| `401`、`403`、`413`            | 公共登录、来源或请求体限制               |
| `429 / RATE_LIMITED`           | 本地语音频率 / 并发限制                  |
| `429 / SPEECH_UPSTREAM_FAILED` | 上游返回 429                             |
| `502 / SPEECH_UPSTREAM_FAILED` | 上游失败、超时、响应无效；不透传原始错误 |
| `503 / SPEECH_NOT_CONFIGURED`  | 未配置能力                               |

TTS 返回头和音频流开始后失败，会直接断流，不把错误 JSON 拼进音频。即使已收到 `200` 也要处理读取异常，不能把不完整音频视为完整生成。

## 9. 调用示例

以下命令供本地手动联调，会创建会话、上传文件或调用付费能力，阅读文档不需要执行。示例均为占位数据，请使用本机测试账号和测试文件，Cookie 文件不要提交。

### 9.1 准备请求环境

以下示例使用预先取得的有效登录 Cookie 文件（curl / Netscape 格式），不包含账号认证流程。将 `COOKIE_JAR` 替换为实际文件路径，Cookie 的来源须与 `API_BASE` 一致。

```sh
API_BASE='http://localhost:8095'
API_ORIGIN='http://localhost:8095'
COOKIE_JAR='/absolute/path/session-cookies.txt'
```

### 9.2 创建会话与获取分支

```sh
curl --fail-with-body -sS -b "$COOKIE_JAR" \
  -H "Origin: $API_ORIGIN" \
  -H 'Content-Type: application/json' \
  -d '{}' "$API_BASE/api/conversations"

# 从上述响应复制真实 id 与 revision。
CONVERSATION_ID='replace-with-conversation-id'
curl --fail-with-body -sS -b "$COOKIE_JAR" \
  "$API_BASE/api/conversations/$CONVERSATION_ID?view=branch"

curl --fail-with-body -sS -b "$COOKIE_JAR" \
  "$API_BASE/api/conversations?limit=50"
```

### 9.3 发起流式生成与读取事件

下面的 `expectedRevision=0` 适用于刚创建且未更新的会话；已有会话须填写实际版本。逻辑操作使用新键，原请求重试则完整保留键与字段。

```sh
curl --fail-with-body -sS -N -b "$COOKIE_JAR" \
  -H "Origin: $API_ORIGIN" \
  -H 'Content-Type: application/json' \
  -H 'Accept: text/event-stream' \
  -d '{"expectedRevision":0,"operation":"send","content":"你好","parentId":null,"thinking":false,"search":false,"idempotencyKey":"55555555-5555-4555-8555-555555555555"}' \
  "$API_BASE/api/conversations/$CONVERSATION_ID/generations?view=branch"
```

### 9.4 取消、更新与删除

在另一个终端使用相同 Cookie 文件，`RUN_ID` 从原流的 `runId` 获取：

```sh
RUN_ID='replace-with-run-id'
curl --fail-with-body -sS -b "$COOKIE_JAR" \
  -H "Origin: $API_ORIGIN" -X POST \
  "$API_BASE/api/generations/$RUN_ID/cancel"

# 等待收尾后重新查询会话，从响应取得最新 revision。
curl --fail-with-body -sS -b "$COOKIE_JAR" \
  "$API_BASE/api/conversations/$CONVERSATION_ID?view=branch"

# 将示例版本 2 改成刚查询的实际版本。
curl --fail-with-body -sS -b "$COOKIE_JAR" \
  -H "Origin: $API_ORIGIN" -H 'Content-Type: application/json' \
  -X PATCH -d '{"expectedRevision":2,"title":"新的标题"}' \
  "$API_BASE/api/conversations/$CONVERSATION_ID?view=branch"

# 重命名后版本已变化；删除前使用最新返回值替换示例版本 3。
curl --fail-with-body -sS -b "$COOKIE_JAR" \
  -H "Origin: $API_ORIGIN" -H 'Content-Type: application/json' \
  -X DELETE -d '{"expectedRevision":3}' \
  "$API_BASE/api/conversations/$CONVERSATION_ID"
```

### 9.5 上传附件与核对

```sh
# 一个上传任务复用同一个 UUID，新的独立上传任务使用新 UUID。
UPLOAD_KEY='66666666-6666-4666-8666-666666666666'
curl --fail-with-body -sS -b "$COOKIE_JAR" \

curl --fail-with-body -sS -b "$COOKIE_JAR" \

```

仅在 `status=ready` 时，将其业务 `id` 加到 `send` / `edit` 的 `attachmentIds`，例如 `{"expectedRevision":0,"operation":"send","content":"总结附件","attachmentIds":["77777777-7777-4777-8777-777777777777"],"idempotencyKey":"88888888-8888-4888-8888-888888888888"}`。使用真实会话版本、附件 ID 和新的操作键；不要传 `serverId`。

### 9.6 ASR 与 TTS

```sh
curl --fail-with-body -sS -b "$COOKIE_JAR" \
  -H "Origin: $API_ORIGIN" \
  -F 'file=@/absolute/path/recording.wav;type=audio/wav' \
  "$API_BASE/api/speech/asr"

curl --fail-with-body -sS -b "$COOKIE_JAR" \
  -H "Origin: $API_ORIGIN" -H 'Content-Type: application/json' \
  -d '{"text":"你好，欢迎使用。","voice":"stella"}' \
  -o /tmp/deepseek-speech.pcm \
  "$API_BASE/api/speech/tts"
```

仅在请求成功且流完整结束后，将输出按 24 kHz / PCM16LE / 单声道播放。curl 失败时输出文件可能包含错误 JSON 或部分数据，不能直接播放。使用其他前端客户端时，保留相同的 Cookie、Origin 和流读取规则。
