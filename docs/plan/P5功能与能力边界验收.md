# P5 功能与能力边界验收

## 本轮范围

推进联网搜索、读链接、引用与工具上下文的一致性和安全检查，以及界面能力提示。附件已确定只用 DeepSeek Files API，语音仍需补齐真实 ASR 与浏览器播放验收，不以界面按钮或 mock 测试推断能力已经可用。

仅本地开发与 Neon dev；不处理旧浏览器数据，不创建未授权的对象存储资源，不提交、推送或部署。P3/P4 未完成验收项保持开放。

## 后续确定的附件方案

用户选择只用 DeepSeek Files API，不引入 R2/Neon Object Storage。新上传原件只在当前页内存中暂存预览，刷新/跨设备仅保留元数据和模型引用，不能下载原件，不读取旧浏览器数据库。

业务默认限制：8 MiB/文件、10个/消息、100个且100 MiB/用户；图片尺寸不超过4096×4096。支持PNG/JPEG/GIF/WebP（首版不支持动画WebP）、PDF、txt/md/csv/json/log/js/ts/py/css/java/go/rs UTF-8文本。Office/电子书/SVG/HTML不在首版白名单。格式校验不等同恶意文件扫描。

供应商file_id只在服务端保存，客户端使用业务attachmentId。图片/文档调用均带Files beta头，PDF上传purpose在file之前。整个历史的文档引用累计计数，JSON请求预算不包括供应商解码后的文档内容。

上传超时/断开可能仍解析并计费，不自动重传；结果未知仍占配额。删除仅可恢复状态，已引用附件不能通过移除破坏历史；不调用供应商DELETE、不自动永久清理。确需永久清理时另行取得具体授权。

存储选择及业务限制已确认实现，P5-02完成；P5-03/04保留后续真实/并发/清理验收缺口。

## 用户消息图片预览修复

原实现 MessageFile 固定显示元数据，且发送被接受后立即释放草稿 objectURL，导致刚发送的图片在同一页也无法预览。现改为：只在服务端确认本次新消息后，按业务附件ID保存独立的当前页图片 objectURL；消息内显示缩略图，点击弹窗查看，草稿仍独立释放。发送失败保留草稿，不创建已发送图片缓存。

预览缓存最多20张/32MiB，超限LRU回收；退出/离页清空，删除会话按引用释放。不读旧IndexedDB、不保存后端原件、不引入R2。刷新/换设备/缓存回收后仍仅元数据；本次修复前已释放的图片不能自动恢复。

新增3项自动化覆盖接受/拒绝、身份退出/无缓存、LRU及共享引用。前端37项、类型、lint、构建通过；未用用户个人文件做供应商上传，也没有新的浏览器视觉实测。
